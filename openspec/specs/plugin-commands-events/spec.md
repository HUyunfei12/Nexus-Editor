## Purpose

本能力为 Nexus 插件定义以语义命令为中心的用户操作与类型化事件契约，使命令可动态注册、查询可用性并获得正确编辑器上下文，使用户快捷键和临时作用域能够确定性仲裁，同时让普通通知事件与可取消的真实 DOM 编辑器事件具备清晰、可测试且相互隔离的分发语义。

## Requirements

### Requirement: 命令命名空间与动态所有权
插件注册命令时 MUST 提供在插件内部唯一且稳定的本地 ID；运行时 MUST 以插件 ID 和本地 ID 组成全局命令 ID，并将命令登记为注册组件所有的资源。命令注册、移除和插件卸载 MUST 原子更新命令面板、快捷键解析和程序化命令查询所观察到的同一命令集合。

#### Scenario: 注册插件命令
- **WHEN** ID 为 `sample-tools` 的插件注册本地 ID 为 `format-selection` 的有效命令
- **THEN** 运行时 MUST 将其发布为全局唯一 ID `sample-tools:format-selection`
- **AND** 命令面板、快捷键服务和程序化查询 MUST 指向同一个命令定义

#### Scenario: 同一插件注册重复命令
- **WHEN** 同一插件所有权范围再次注册一个仍然存在的相同本地命令 ID
- **THEN** 运行时 MUST 原子拒绝后一次注册并返回命名冲突诊断
- **AND** 先前命令及其他插件的同名本地命令 MUST 保持不变

#### Scenario: 命令所有者卸载
- **WHEN** 注册命令的组件被移除或其插件开始卸载
- **THEN** 运行时 MUST 在所有者卸载完成前从全部命令入口移除该命令及其默认快捷键贡献
- **AND** 已保存的用户快捷键配置 MUST 可保留为失效映射，以便同一全局命令 ID 将来恢复时继续使用

### Requirement: 命令执行模式必须唯一
每个命令定义 MUST 且只能提供 `callback`、`checkCallback`、`editorCallback` 或 `editorCheckCallback` 四种执行模式之一；运行时不得使用隐式优先级猜测应执行哪个回调。缺少执行模式或同时提供多个执行模式的定义 MUST 在发布前被拒绝。

#### Scenario: 同时声明多个回调
- **WHEN** 插件提交同时包含 `callback` 与 `editorCallback` 的命令定义
- **THEN** 运行时 MUST 拒绝整个命令注册并返回执行模式无效诊断
- **AND** 命令面板和快捷键服务 MUST 从未观察到该无效命令

#### Scenario: 声明恰好一个执行模式
- **WHEN** 插件提交仅包含四种执行模式之一且其余字段有效的命令
- **THEN** 运行时 MUST 根据该执行模式注册命令而不要求空占位回调
- **AND** 后续可用性探测与执行 MUST 始终使用注册时选定的同一模式

### Requirement: 无副作用的命令可用性探测
运行时 MUST 能在不执行命令副作用的情况下判断命令当前是否可用。`checkCallback` 与 `editorCheckCallback` 在探测阶段 MUST 收到明确的检查标志并只返回可用性；真正执行前 MUST 重新检查当前状态，以避免命令面板展示与用户触发之间的状态变化导致过期执行。探测失败或抛错 MUST 使该命令在本次查询中不可用并产生诊断。

#### Scenario: 命令面板探测条件命令
- **WHEN** 命令面板查询一个使用检查回调的命令是否可用
- **THEN** 运行时 MUST 以检查模式调用该回调并依据其结果展示或隐藏命令
- **AND** 检查模式调用 MUST 不执行命令动作、修改文档或写入插件设置

#### Scenario: 状态在探测后发生变化
- **WHEN** 条件命令探测时可用但在用户触发前其前置条件已失效
- **THEN** 运行时 MUST 在执行时以非检查模式重新验证并拒绝过期动作
- **AND** 拒绝执行 MUST 返回“当前不可用”结果，而不是调用先前缓存的动作

#### Scenario: 可用性探测抛错
- **WHEN** 命令的检查回调在探测阶段抛出错误或拒绝 Promise
- **THEN** 运行时 MUST 将该命令视为本次探测不可用并继续查询其他命令
- **AND** 运行时 MUST 产生归属于该全局命令 ID 和插件的隔离诊断

### Requirement: 编辑器命令使用执行时上下文
`editorCallback` 与 `editorCheckCallback` MUST 仅在存在活动且可操作的编辑器时可用。运行时 MUST 在每次探测和执行时重新解析编辑器上下文，并向回调提供当前编辑器以及对应文档或视图信息；不得持有注册时或上一次探测时的过期编辑器实例。

#### Scenario: 活动编辑器存在
- **WHEN** 用户在一个活动编辑器中探测并执行编辑器命令
- **THEN** 回调 MUST 收到触发时的编辑器实例和与其匹配的文档或视图上下文
- **AND** 命令产生的编辑操作 MUST 作用于该触发时编辑器而非其他后台编辑器

#### Scenario: 没有活动编辑器
- **WHEN** 当前焦点视图不提供可操作编辑器或编辑器在触发前已关闭
- **THEN** 编辑器命令 MUST 被报告为不可用且不得调用其执行回调
- **AND** 普通全局命令的可用性 MUST 不受该情况影响

### Requirement: 用户快捷键覆盖与 Mod 规范化
快捷键 MUST 是语义命令的可配置绑定，而不是命令实现本身。运行时 MUST 保存并优先采用用户绑定，允许用户替换或清除插件提供的默认绑定，且插件更新不得覆盖用户选择。`Mod` MUST 在 macOS 解析为 `Meta`，在 Windows 和 Linux 解析为 `Ctrl`；字母键与修饰键 MUST 经过一致规范化后再参与匹配和冲突检测。

#### Scenario: 用户覆盖默认快捷键
- **WHEN** 插件为命令贡献默认快捷键而用户为该命令保存了不同绑定
- **THEN** 运行时 MUST 只使用用户绑定作为当前有效快捷键
- **AND** 插件重新加载或升级 MUST 不得恢复默认绑定覆盖用户配置

#### Scenario: 跨平台解析 Mod
- **WHEN** 同一用户绑定使用 `Mod+V` 并分别在 macOS 与 Windows 宿主解析
- **THEN** 运行时 MUST 分别匹配 `Meta+V` 与 `Ctrl+V`
- **AND** 该键盘绑定 MUST 只触发相应命令，不得伪造或替代真实的 `paste` DOM 事件

#### Scenario: 用户清除快捷键
- **WHEN** 用户显式清除某命令的全部快捷键绑定
- **THEN** 运行时 MUST 保持该命令可从命令面板或程序化入口调用
- **AND** 运行时 MUST 不得退回插件默认快捷键，除非用户显式恢复默认值

### Requirement: Scope 栈与快捷键冲突仲裁
运行时 MUST 提供具有父级继承关系的快捷键 `Scope`，并通过栈确定当前活动作用域。键盘事件 MUST 从栈顶作用域开始，沿父作用域和应用作用域查找候选；高层作用域中明确处理的事件 MUST 遮蔽低层候选，未处理的事件 MUST 继续向下解析。作用域 MUST 绑定所有者并在视图关闭或插件卸载时自动移出栈。

#### Scenario: 临时作用域遮蔽全局绑定
- **WHEN** 模态框作用域位于栈顶且处理了一个与全局命令相同的规范化快捷键
- **THEN** 运行时 MUST 只执行模态框作用域的处理器并停止查找低层绑定
- **AND** 处理结果要求取消默认行为时，原始键盘事件 MUST 被同步 `preventDefault`

#### Scenario: 顶层作用域拒绝处理
- **WHEN** 栈顶作用域的候选处理器检查上下文后返回未处理
- **THEN** 运行时 MUST 按父作用域到应用作用域的顺序继续解析该键盘事件
- **AND** 首个明确处理事件的低层候选 MUST 成为唯一执行的动作

#### Scenario: 同一优先级存在冲突
- **WHEN** 同一有效作用域内有两个用户绑定或两个同优先级处理器竞争同一规范化快捷键且无更高优先规则可区分
- **THEN** 运行时 MUST 将该组合标记为冲突并不得依据插件加载顺序任意选择一个动作
- **AND** 宿主 MUST 向用户和相关插件提供包含全部候选命令 ID 的冲突诊断

#### Scenario: 作用域所有者被卸载
- **WHEN** 活动作用域所属视图关闭或插件卸载
- **THEN** 运行时 MUST 自动将该作用域及其处理器从作用域栈移除
- **AND** 后续相同按键 MUST 重新由仍然活动的父级或应用级绑定解析

### Requirement: 类型化事件与可释放订阅
每个事件服务 MUST 通过稳定的事件映射定义事件名及其载荷类型，并在订阅时返回不透明、可幂等释放的订阅引用。订阅 MUST 能登记给组件所有者以便自动释放；释放订阅后，处理器不得再收到新的事件。运行时对未知事件名或不符合已注册事件契约的发射 MUST 返回诊断，而不得静默以任意参数调用处理器。

#### Scenario: 订阅类型化事件
- **WHEN** 插件订阅一个已声明的文件或编辑器事件
- **THEN** 处理器 MUST 只收到该事件契约定义的载荷字段和上下文
- **AND** 返回的订阅引用 MUST 可由调用方主动释放或由所属组件卸载时自动释放

#### Scenario: 重复释放订阅
- **WHEN** 同一订阅引用被主动释放后又因所有者卸载而再次释放
- **THEN** 第二次及后续释放 MUST 无副作用且不得抛出错误
- **AND** 该处理器 MUST 不再接收释放之后发射的事件

#### Scenario: 订阅未知事件
- **WHEN** 运行时代码尝试订阅当前服务未声明的事件名
- **THEN** 事件服务 MUST 拒绝该订阅并返回包含服务与事件名的诊断
- **AND** 事件服务 MUST 不得创建一个无法被类型契约描述的隐式事件通道

### Requirement: 通知事件与可取消 DOM 事件语义分离
普通通知事件 MUST 只传播事实，其处理器返回值不得取消宿主行为或阻止其他订阅者。粘贴、剪切、复制、拖放、键盘和上下文菜单等需要接管浏览器默认行为的编辑器事件 MUST 暴露实际 DOM 事件或等价的同步可取消对象；处理器 MUST 通过 `defaultPrevented` 判断是否已处理，并通过 `preventDefault()` 明确接管。物理快捷键不得替代剪贴板事件语义。

#### Scenario: 普通通知事件处理器返回值
- **WHEN** 一个普通文档变更通知的处理器返回 `false`、`true` 或其他值
- **THEN** 运行时 MUST 忽略该返回值并继续向其他有效订阅者发送通知
- **AND** 宿主已经发生的文档变更 MUST 不因通知处理器返回值而回滚

#### Scenario: 插件接管真实粘贴事件
- **WHEN** 编辑器收到尚未被处理的真实 `ClipboardEvent` 且插件同步调用 `preventDefault()`
- **THEN** 后续处理器 MUST 能从 `defaultPrevented` 观察到该事件已被接管
- **AND** 宿主 MUST 跳过默认粘贴动作，但不得把 `preventDefault()` 隐式解释为停止所有后续观察者

#### Scenario: 异步代码尝试取消默认行为
- **WHEN** 可取消事件处理器在同步分发结束后才从异步任务调用 `preventDefault()`
- **THEN** 宿主 MUST 依据同步分发结束时的取消状态决定是否执行默认动作
- **AND** 迟到的取消 MUST 不得撤销已经执行的宿主行为

#### Scenario: 通过菜单触发剪贴板操作
- **WHEN** 用户通过系统菜单或上下文菜单触发复制、剪切或粘贴而没有对应 `Ctrl/Cmd` 键盘事件
- **THEN** 已订阅相应 DOM 剪贴板事件的插件 MUST 仍有机会观察或接管该操作
- **AND** 仅注册命令快捷键或 `Scope` 处理器的插件 MUST 不得被视为已拦截该剪贴板操作

### Requirement: 确定性事件优先级与分发快照
事件订阅 MUST 支持显式优先级；较高优先级处理器 MUST 先执行，相同优先级 MUST 按注册顺序执行。每次发射 MUST 使用在分发开始时建立的订阅快照：分发期间新增的订阅只能参与后续发射，已在轮到前释放的订阅不得再执行。优先级不得由插件加载顺序、对象枚举顺序或未公开宿主细节推断。

#### Scenario: 按优先级分发事件
- **WHEN** 同一事件拥有优先级 100、0、0 和 -10 的四个有效订阅
- **THEN** 运行时 MUST 先执行优先级 100，随后按注册顺序执行两个优先级 0，最后执行优先级 -10
- **AND** 对相同订阅集合的后续发射 MUST 保持相同确定性顺序

#### Scenario: 分发期间修改订阅集合
- **WHEN** 一个处理器在事件分发期间新增订阅并释放一个尚未执行的订阅
- **THEN** 新订阅 MUST 从下一次事件发射起才有资格执行
- **AND** 已释放且尚未轮到的订阅 MUST 在当前分发中被跳过

### Requirement: 事件重入与异常隔离
同一事件通道在处理器执行期间再次发射相同事件时，运行时 MUST 将嵌套发射排入先进先出队列，当前分发不得同步递归进入自身。宿主 MUST 对一次事件循环采用已记录的有限分发预算，超过预算时终止剩余重入并产生诊断。单个通知处理器抛错不得阻止其余处理器；可取消事件只有显式 `preventDefault()` 才能取消默认动作，异常本身不得隐式取消。

#### Scenario: 处理器重入发射同一事件
- **WHEN** 一个事件处理器在处理事件 A 时再次发射事件 A
- **THEN** 第二次事件 A MUST 在当前事件 A 的有效处理器全部完成后按先进先出顺序分发
- **AND** 当前调用栈 MUST 不得因相同事件的连续重入而无限增长

#### Scenario: 重入超过分发预算
- **WHEN** 处理器持续重新发射同一事件并超过宿主公开的有限分发预算
- **THEN** 运行时 MUST 终止该事件循环中尚未处理的嵌套发射
- **AND** 运行时 MUST 产生包含事件名、来源插件和预算信息的重入诊断，同时保持其他事件通道可用

#### Scenario: 通知处理器抛错
- **WHEN** 高优先级普通通知处理器抛出未捕获错误
- **THEN** 运行时 MUST 记录归属于该订阅所有者的诊断并继续执行其余有效处理器
- **AND** 该异常 MUST 不得穿透事件服务边界或自动释放其他插件的订阅

#### Scenario: 可取消事件处理器抛错
- **WHEN** 可取消 DOM 事件处理器在未调用 `preventDefault()` 的情况下抛出错误
- **THEN** 运行时 MUST 隔离并诊断该错误，同时继续完成同步分发
- **AND** 宿主 MUST 仅依据最终 `defaultPrevented` 状态决定默认动作，不得把异常等同于取消

### Requirement: 命令与快捷键执行错误隔离
命令回调和 `Scope` 处理器 MUST 在所属插件边界内执行。命令回调失败 MUST 返回可诊断的失败结果而不破坏命令注册表；快捷键候选开始执行后发生异常 MUST 被视为该键已被处理，以避免执行低层候选或浏览器默认动作造成重复副作用，同时不得影响后续独立键盘事件。

#### Scenario: 命令回调失败
- **WHEN** 用户从命令面板执行的插件命令抛出错误或拒绝 Promise
- **THEN** 运行时 MUST 向调用入口返回失败结果并产生包含全局命令 ID 的诊断
- **AND** 其他命令、事件订阅和无依赖插件 MUST 继续保持可用

#### Scenario: Scope 处理器执行中抛错
- **WHEN** 已选中的顶层 `Scope` 处理器在产生部分副作用后抛出错误
- **THEN** 运行时 MUST 诊断该错误、停止解析该按键的低层候选并阻止浏览器默认动作
- **AND** 作用域栈 MUST 保持一致，使下一次独立键盘事件仍可正常仲裁
