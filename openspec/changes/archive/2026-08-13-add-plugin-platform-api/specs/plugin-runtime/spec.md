## Purpose

本能力为 Nexus 插件提供宿主无关且可验证的运行时契约，使插件能够通过稳定的应用门面发现宿主能力，并以明确的组件所有权、生命周期状态、自动资源回收、失败回滚和结构化诊断安全地装载与卸载，而不依赖 Electron、Node 或任一宿主的内部对象。

## ADDED Requirements

### Requirement: 宿主应用门面与能力发现
运行时 MUST 为每个插件注入只读的 `NexusApp` 门面、规范化后的插件身份和宿主版本信息；门面 MUST 只暴露宿主声明支持的稳定服务与能力查询，不得向插件泄露宿主内部管理器或全局应用单例。能力查询 MUST 区分“不支持该能力”“支持的能力版本不满足要求”和“能力可用”，并允许插件在调用服务之前完成检测。

#### Scenario: 所需能力全部满足
- **WHEN** 插件声明的全部必需能力都由宿主提供且版本满足约束
- **THEN** 运行时 MUST 在调用插件 `onload` 前向插件提供同一宿主上下文中的可用服务
- **AND** 每次针对同一能力的发现结果 MUST 在该插件本次加载期间保持一致

#### Scenario: 必需能力缺失
- **WHEN** 插件的一项必需能力不存在或其版本低于插件要求
- **THEN** 运行时 MUST 在执行任何插件生命周期代码之前拒绝加载该插件
- **AND** 运行时 MUST 产生包含插件身份、能力标识、期望约束和实际结果的兼容诊断

#### Scenario: 可选能力缺失
- **WHEN** 插件查询一项宿主未提供的可选能力
- **THEN** 能力查询 MUST 返回明确的不可用结果而非抛出未定义错误
- **AND** 插件 MUST 仍可继续加载并使用其他可用能力

### Requirement: 插件生命周期状态机
每个插件实例 MUST 遵循 `constructed -> loading -> loaded -> unloading -> unloaded` 的正常状态转换；加载失败的实例 MUST 在完成回滚后进入 `failed` 状态。运行时 MUST 串行化同一实例的生命周期操作，且 `onload` 与 `onunload` 对该实例均不得执行超过一次。`unloaded` 和 `failed` MUST 是不可再次加载的终态；重新启用插件 MUST 创建新的插件实例。

#### Scenario: 正常加载与卸载
- **WHEN** 宿主加载一个处于 `constructed` 状态且预检通过的插件实例
- **THEN** 运行时 MUST 先将其置为 `loading`，等待 `onload` 成功完成后再置为 `loaded`
- **AND** 卸载时 MUST 将其置为 `unloading`，等待所有托管清理完成后再置为 `unloaded`

#### Scenario: 加载期间收到卸载请求
- **WHEN** 插件仍处于 `loading` 状态时宿主请求卸载
- **THEN** 运行时 MUST 串行处理该请求并等待当前加载操作得到成功或失败结果
- **AND** 运行时 MUST 在返回卸载结果前完成正常卸载或失败回滚，且不得并发执行 `onload` 与 `onunload`

#### Scenario: 尝试重新加载终态实例
- **WHEN** 宿主对处于 `unloaded` 或 `failed` 状态的同一插件实例再次请求加载
- **THEN** 运行时 MUST 拒绝该请求并返回稳定的生命周期错误
- **AND** 运行时 MUST 不再执行该实例的任何加载钩子或重新发布其贡献

### Requirement: Component 单一所有者树
插件和可复用子组件 MUST 形成无环的单一所有者树。一个组件在任一时刻最多只能拥有一个父组件；向已加载父组件添加子组件 MUST 触发子组件加载，从父组件移除子组件 MUST 触发子组件卸载。父组件卸载完成前 MUST 先卸载全部子组件，使子组件持有的资源不会晚于所有者存活。

#### Scenario: 在父组件加载前添加子组件
- **WHEN** 子组件被添加到尚未加载的父组件
- **THEN** 子组件 MUST 保持未加载，直到父组件开始加载
- **AND** 父组件 MUST 按添加顺序加载其仍然归属自己的子组件

#### Scenario: 向已加载父组件添加和移除子组件
- **WHEN** 一个未加载子组件被添加到已处于 `loaded` 状态的父组件并随后被移除
- **THEN** 运行时 MUST 在添加操作完成前加载该子组件，并在移除操作完成前卸载该子组件
- **AND** 移除后的子组件 MUST 不再接收由原父组件托管的回调或服务通知

#### Scenario: 父组件级联卸载
- **WHEN** 一个拥有多个已加载子组件的父组件开始卸载
- **THEN** 运行时 MUST 按与添加顺序相反的顺序完成子组件卸载
- **AND** 父组件的卸载结果 MUST 在所有子组件均完成清理之后才可完成

#### Scenario: 非法所有权关系
- **WHEN** 调用方尝试让组件拥有第二个父组件、拥有自身或形成祖先环
- **THEN** 运行时 MUST 原子地拒绝该所有权变更
- **AND** 原有组件树、组件状态和已注册资源 MUST 保持不变

### Requirement: 统一资源注册与自动清理
每个组件 MUST 能登记同步或异步 disposer，并能通过事件、DOM 监听器和计时器等专用注册入口登记资源；所有专用入口 MUST 具有与通用 disposer 相同的所有权和卸载保证。组件卸载时，运行时 MUST 按登记顺序的逆序执行尚未执行的 disposer，每个 disposer 最多执行一次，并在卸载结果完成前等待异步 disposer 结束。

#### Scenario: 按依赖逆序清理资源
- **WHEN** 已加载组件依次登记资源 A、B、C 后开始卸载
- **THEN** 运行时 MUST 按 C、B、A 的顺序执行相应 disposer
- **AND** 所有成功登记的事件监听、DOM 监听和计时器 MUST 在卸载完成后失效

#### Scenario: 登记后主动释放资源
- **WHEN** 插件在组件卸载前主动调用某项已登记资源的 disposer
- **THEN** 该资源 MUST 立即释放且其 disposer MUST 被标记为已执行
- **AND** 后续组件卸载 MUST 跳过该 disposer，不得产生第二次释放副作用

#### Scenario: 在清理阶段登记新资源
- **WHEN** 组件已经进入 `unloading`、`unloaded` 或 `failed` 状态后代码尝试登记新资源
- **THEN** 运行时 MUST 拒绝托管该资源并立即调用随请求提供的 disposer
- **AND** 运行时 MUST 记录资源晚注册诊断，从而不留下失去所有者的资源

### Requirement: 加载失败的原子回滚
插件或任一子组件的加载钩子抛错、拒绝 Promise 或返回失败结果时，运行时 MUST 将本次加载视为整体失败。运行时 MUST 停止发布尚未可见的插件贡献，按资源与组件获取顺序的逆序回滚本次加载产生的所有副作用，并只在回滚完成后报告加载失败。

#### Scenario: 插件加载钩子失败
- **WHEN** 插件在 `onload` 中已注册命令、事件和子组件后抛出错误
- **THEN** 运行时 MUST 撤销本次加载产生的全部命令、订阅、子组件和其他托管资源
- **AND** 该插件 MUST 不得以部分加载状态出现在可用插件或贡献列表中

#### Scenario: 子组件加载失败
- **WHEN** 父组件加载过程中某一子组件失败而较早的兄弟组件已成功加载
- **THEN** 运行时 MUST 卸载失败子组件已获取的资源以及本次已加载的兄弟组件
- **AND** 父插件 MUST 进入 `failed` 状态并产生指出失败组件路径的诊断

#### Scenario: 回滚操作自身失败
- **WHEN** 加载失败后的一个或多个 disposer 在回滚期间也发生错误
- **THEN** 运行时 MUST 继续执行其余回滚操作而不得在首个清理错误处停止
- **AND** 最终加载结果 MUST 同时保留原始加载错误和所有回滚错误的结构化诊断

### Requirement: 幂等且完备的卸载
对同一插件或组件的重复、并发卸载请求 MUST 共享同一卸载结果；运行时 MUST 保证卸载钩子、子组件卸载和每项 disposer 各执行至多一次。卸载中的单项清理失败不得阻止其他资源清理，最终结果 MUST 明确区分“已完整卸载”和“已卸载但发生清理错误”。

#### Scenario: 重复并发卸载
- **WHEN** 宿主同时或先后多次请求卸载同一已加载插件
- **THEN** 所有调用 MUST 等待或获得同一个终态结果，且插件最终 MUST 为 `unloaded`
- **AND** `onunload`、子组件卸载与已登记 disposer MUST 各自只执行一次

#### Scenario: 卸载钩子抛错
- **WHEN** 插件 `onunload` 或某项资源清理抛出错误
- **THEN** 运行时 MUST 继续清理其余子组件和资源并使插件离开活动集合
- **AND** 卸载结果 MUST 携带清理错误诊断，且插件不得因该错误恢复到 `loaded` 状态

### Requirement: 插件隔离与结构化诊断
运行时 MUST 在插件边界隔离预检、加载、回调、回滚和卸载错误，使单个插件失败不会中断其他插件的生命周期或宿主主循环。每项诊断 MUST 至少包含稳定错误码、插件 ID 与版本、生命周期阶段、相关能力或资源标识和可追踪的原因；诊断不得包含其他插件的私有数据、密钥值或未经处理的用户内容。

#### Scenario: 一个插件加载失败但其他插件正常
- **WHEN** 宿主批量加载多个插件且其中一个插件在加载阶段失败
- **THEN** 运行时 MUST 仅回滚并停用失败插件，继续处理彼此无依赖的其他插件
- **AND** 宿主 MUST 能通过结构化诊断将失败准确归因到对应插件和生命周期阶段

#### Scenario: 插件运行期回调越界失败
- **WHEN** 已加载插件的托管回调抛出未捕获错误
- **THEN** 运行时 MUST 阻止该错误穿透插件边界并影响宿主或其他插件
- **AND** 运行时 MUST 报告经过敏感信息过滤的回调诊断，同时保持该插件后续处置策略可由宿主观察
